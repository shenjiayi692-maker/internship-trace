实习三个月，写简历时想不起自己到底做过什么，而简历要的恰恰是细节。

```bash
git clone https://github.com/shenjiayi692-maker/internship-trace && cd internship-trace && npm i && npm test
```

这会在平台无关的内核上跑测试——证据评分、脱敏、90 天保留、JD 匹配——不需要任何微信工具链。要看界面仍然需要微信开发者工具，见下方。

实习迹是一个微信小程序高保真原型，把每天零散的工作变成可检视、可复用的职业证据。它记下一件小事，最多追问两个问题，并让此后生成的每一份周报、JD 匹配、CV 要点和面试追问，都始终连回它的来源证据。

## 证据链

```text
每日记录 → 追问 → 事实卡 → 确认 → 周报 / JD 匹配 / CV / 面试
```

整个原型围绕一条规则设计：生成的措辞可以变，但不得增加任何未经确认的数字或结果。

- 用文字或模拟的语音转写流程记录
- 为证据完整度打分，并提示缺失的上下文
- 敏感文本在进入可复用的事实层之前先脱敏
- 把岗位要求匹配到已有证据——并如实显示缺口
- 生成周报、CV 要点和有针对性的面试问题
- 任何生成内容都能反向打开，看到支撑它的事实卡
- 本地导出为复制文本或 Canvas 渲染的报告长图

## 试用原型

1. 用 `npm install` 安装依赖。
2. 打开微信开发者工具，导入仓库根目录。
3. 用已配置的 `touristappid` 编译。
4. 从隐私页开始，然后依次走「今日 → 资产 → 生成」。

建议的体验路径：

1. 添加一条文字或语音形式的每日记录。
2. 回答或跳过最多两个追问。
3. 确认生成的事实卡，必要时补充结果。
4. 生成一份周报，或粘贴一份 JD 做模拟分析。
5. 检视某条 CV 要点背后的来源，以及它对应的面试追问。
6. 在「我的」里导出数据、恢复示例数据集，或彻底删除。

## 原型边界

本仓库让可评审的交互是真的，同时把外部系统全部保持为模拟：

- 所有产品数据留在微信本地存储。
- 没有账号、网络请求、云函数、模型 SDK，也没有支付。
- AI 追问、整理、生成、OCR 和语音转写都是确定性模拟。
- 语音路径会申请麦克风权限，但不录音、不留存音频。
- JD 截图使用微信临时路径，模拟识别后即释放。

它不是一个可上线的小程序。

## 可移植内核

| 包 | 职责 |
| --- | --- |
| `apps/wechat-miniprogram/` | 原生 WXML、WXSS、TypeScript 页面、组件和微信适配层 |
| `packages/core/` | 平台无关的评分、脱敏、保留、生成和匹配规则 |
| `packages/contracts/` | 领域类型、可替换的端口，以及连贯的示例数据 |
| `scripts/` | 项目结构与边界检查 |

core 和 contracts 两个包不允许依赖 `wx`、浏览器 API 或任何模型 SDK。未来做 PWA 时，只需替换页面层，证据规则不用重写。

## 验证

建议 Node.js 22 或更新版本。

```bash
npm install
npm test
npm run typecheck
npm run check
```

测试覆盖证据评分、最多两次追问的上限、脱敏、90 天保留、JD 匹配、风险标记和来源追溯。

## 数据规则

- 原始记录 90 天后到期，第 83 天进入提醒窗口。
- 到期清除原始来源，但保留事实卡，并标记来源已清理。
- 未确认的数字会变成可见的风险标记，而不是已验证的结果。
- 每一件生成产物都带有事实卡 ID，可以在资产库里检视。

## 做真实 MVP 之前

生产版本需要服务端模型代理、供应商的数据保留设置、匿名会话设计、请求脱敏、成本限额、真实的语音转写与 OCR、订阅消息、隐私文档，以及平台审核。模型密钥绝不能嵌进小程序里。
